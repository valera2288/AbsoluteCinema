# Absolute Cinema

Учебный стенд курсового проекта «Онлайн-кинотеатр». Доступны каталог с трейлерами, регистрация и профили зрителей, учебное оформление подписки, просмотр фильмов, отзывы и административные функции.

## Подготовка и запуск в PowerShell

Нужны Python 3.13, PostgreSQL 17 и существующая локальная база `online_cinema`. Установка не меняет системный Python.

Для повседневного запуска подготовленного стенда выполни в папке проекта:

```powershell
.\start-local.ps1
```

При первом запуске скрипт попросит пароль PostgreSQL и проверит подключение к `online_cinema:5433`. Ключ Django и пароль сохраняются в зашифрованном файле `%LOCALAPPDATA%\AbsoluteCinema\local-dev.clixml`, привязанном к текущей учётной записи Windows. Следующие запуски используют сохранённые данные. Если пароль PostgreSQL изменился, запусти `.\start-local.ps1 -ResetDatabasePassword`.

### Первичная установка и ручные команды Django

```powershell
py -3.13 -m venv .venv
$python = '.\.venv\Scripts\python.exe'
& $python -m pip install -r requirements.txt
$env:DB_HOST = '127.0.0.1'
$env:DB_PORT = '5433'
$env:DB_NAME = 'online_cinema'
$env:DB_USER = 'postgres'
if (-not $env:DB_PASSWORD) {
    $password = Read-Host 'Пароль PostgreSQL' -AsSecureString
    $env:DB_PASSWORD = [Net.NetworkCredential]::new('', $password).Password
    $password.Dispose()
}
if (-not $env:DJANGO_SECRET_KEY) {
    $env:DJANGO_SECRET_KEY = & $python -c 'import secrets; print(secrets.token_urlsafe(48))'
}
$env:DJANGO_DEBUG = '1'
& $python manage.py inspect_database
```

`inspect_database` только читает базу, печатает имя, порт, версию сервера, список пользовательских таблиц и записи `django_migrations`. Для первого запуска ожидается `online_cinema:5433` и отсутствие таблиц. Если таблицы уже есть, сначала выясните, какому проекту они принадлежат и какие миграции применены. Не сбрасывайте базу, не используйте `--fake` и не применяйте миграции к непроверенной схеме. Команды ниже запускайте только после этой проверки и в том же терминале.

```powershell
& $python manage.py check
& $python manage.py migrate
& $python manage.py showmigrations
& $python manage.py setup_roles
& $python manage.py createsuperuser
& $python manage.py runserver 127.0.0.1:8000
```

Если администратор уже существует, пропустите `createsuperuser`. При создании введите уникальные логин и email, затем дважды введите пароль. Пароль не отображается и не передаётся аргументом. Главная: `http://127.0.0.1:8000/`; вход администратора: `http://127.0.0.1:8000/admin/`. Вход принимает логин или email без учёта регистра. `setup_roles` можно запускать повторно: команда добавляет недостающие штатные разрешения и не удаляет существующие. Менять аккаунты и роли в Admin может только суперпользователь. Модерация отзывов доступна по назначенным разрешениям.

Не записывайте `DB_PASSWORD` и `DJANGO_SECRET_KEY` в исходники или логи. Команды выше создают секретный ключ только на текущий сеанс PowerShell; с новым ключом потребуется повторный вход. `runserver`, `DJANGO_DEBUG=1` и учебная учётная запись предназначены только для локального стенда.

## Проба защищённой выдачи MP4

1. Можно использовать `private/online-cinema-probe.mp4` — синтетический ролик с тестовым рисунком и тоном (80 секунд, 11,1 МиБ). Для собственного файла возьмите разрешённый MP4 размером от 5 до 20 МиБ, H.264/AAC, с метаданными в начале. Поместите его в закрытую папку вне `static`, `collected-static` и любой другой публичной раздачи. Не добавляйте символических ссылок на файл из публичных папок.
2. В Admin создайте отдельного тестового сотрудника с `is_staff` и добавьте его в группу «Пробный просмотр». Для этой пробы нужна явная группа даже у суперпользователя: так отзыв можно показать без блокировки аккаунта. Попросите тестового сотрудника войти через `/admin/`.
3. В том же терминале остановите сервер, задайте переменные и запустите его снова:

   ```powershell
   $env:DJANGO_MEDIA_PROBE = '1'
   $env:DJANGO_MEDIA_PROBE_FILE = (Resolve-Path -LiteralPath '.\private\online-cinema-probe.mp4').Path
   & $python manage.py runserver 127.0.0.1:8000
   ```

4. В Microsoft Edge откройте `http://127.0.0.1:8000/probe/`. Откройте «Сеть» в инструментах разработчика и отключите кэш. Запустите видео, затем перемотайте в незагруженную область. Ожидается воспроизведение с выбранного места и новый `GET /probe/video/` с заголовком `Range`, ответом `206` и согласованными `Content-Range` и `Content-Length`. Если браузер успевает загрузить файл целиком, ограничьте скорость в инструментах разработчика и повторите.
5. В отдельной сессии администратора снимите у сотрудника группу «Пробный просмотр». В исходной сессии снова перемотайте в ещё не загруженную область: **новый** запрос Range должен вернуть `403` без фрагмента. Уже переданные байты не отзываются. Прямые запросы к `/online-cinema-probe.mp4`, `/private/online-cinema-probe.mp4` и `/static/online-cinema-probe.mp4` должны вернуть `404`.
6. Снимите `DJANGO_MEDIA_PROBE` и `DJANGO_MEDIA_PROBE_FILE` в окружении и перезапустите сервер. `/probe/` и `/probe/video/` должны вернуть `404`. Без `DJANGO_DEBUG=1` маршруты также отсутствуют.

## Серверные проверки

```powershell
Remove-Item Env:DJANGO_MEDIA_PROBE -ErrorAction SilentlyContinue
& $python manage.py makemigrations --check --dry-run
& $python manage.py test
```

Тесты создают отдельную PostgreSQL-базу `test_online_cinema`; для этого у роли должно быть право создавать базы. Не задавайте имена действующих баз в настройках тестовой базы. Тесты проверяют CSRF и вход через обычный маршрут Admin, запись сессии в БД, ограничение служебных прав, два уникальных индекса по `Lower` прямыми вставками без валидации форм, а также ответы выдачи на синтетических байтах. Эти байты не являются воспроизводимым MP4: тесты не заменяют проверку в Edge.

## Этап 2: каталог и публикация

Установите зависимости из `requirements.txt` (Pillow предусмотрен ТЗ для проверки изображений). FFprobe устанавливается отдельно; менять версию Python не нужно.

### FFprobe в Windows

1. Откройте [страницу загрузки FFmpeg](https://ffmpeg.org/download.html#build-windows), выберите актуальную сборку для Windows, например Essentials, и распакуйте её. В папке `bin` должен быть `ffprobe.exe`.
2. Добавьте папку `bin` в пользовательскую переменную `Path` и откройте новый PowerShell. Либо задайте путь только для текущего терминала:

   ```powershell
   $ffmpegBin = 'C:\Tools\ffmpeg\bin'  # укажите фактический путь
   $env:Path = "$ffmpegBin;$env:Path"
   ffprobe -version
   ```

3. Без изменения `Path` можно задать `$env:FFPROBE_BIN = 'C:\Tools\ffmpeg\bin\ffprobe.exe'`. Запускайте Django из этого же терминала. Без FFprobe загрузка MP4 и публикация фильма с MP4 отклоняются.

### Обновление базы и демонстрация

В терминале с `DB_PASSWORD` проверьте базу через `inspect_database` и `showmigrations`. Если миграции этапа 1 на месте, выполните `migrate`, `setup_roles`, `check` и перезапустите локальный сервер. Повторно создавать администратора не нужно. Для оператора каталога нужны `is_staff` и группа «Администраторы» либо отдельные разрешения. Группа также получает доступ к журналу только для чтения.

1. Выполните `& $python manage.py prepare_catalog_demo .\private\demo-art`. Команда создаёт оригинальные `poster.jpg` и `banner.jpg` без изменений БД и перезаписи файлов.
2. В Admin создайте действующий жанр «Фантастика» и фильм «Ночной сигнал»: 2026 год, 2 минуты, 12+, описание «Оператор ночной станции ловит неизвестный сигнал». Выберите жанр. Создайте второй фильм «Тихий горизонт» и оставьте черновиком.
3. В «Медиафайлах» добавьте постер и обложку из `demo-art`. Для трейлера и полного видео загрузите оригинальный `private/online-cinema-probe.mp4` двумя отдельными записями с вариантом `default`. Файлы копируются в закрытое `CATALOG_MEDIA_ROOT` (по умолчанию `private/catalog`), которое нельзя подключать к публичной раздаче.
4. Создайте активный тариф «Киновечер» (299 ₽, 30 дней, два одновременных просмотра) и отключённый «Архивный тариф» (499 ₽, 60 дней, четыре просмотра).
5. Выберите «Опубликовать» в списке фильмов. В Edge откройте главную, найдите фильм в каталоге, перейдите в карточку и запустите трейлер. На странице тарифов должен быть виден только «Киновечер». Сохраните URL трейлера, подтвердите снятие фильма и проверьте `404` по прежним адресам карточки и трейлера.

Минимальный рейтинг проходит проверку, но не влияет на выдачу до этапа 6. При сбое между записью файла и коммитом или при открытом старом файле в Windows возможны лишние файлы. Для очистки после остановки стенда сверяйте имена с `movie_media.storage_key`; не удаляйте файл, если БД на него ссылается.

Для тестов этапа 2 нужны FFprobe и синтетические файлы из `private/`. Для локальной копии FFprobe, распакованной при разработке, используйте `$env:FFPROBE_BIN = (Get-ChildItem .venv/ffmpeg-tools -Recurse -Filter ffprobe.exe | Select-Object -First 1).FullName`. Запускайте тесты на выделенной PostgreSQL, а не на пользовательской базе.

## Этап 3: аккаунты, профили и устройства

Перед обновлением проверьте целевую базу командами `inspect_database`, `showmigrations` и `migrate --plan` из того же терминала, где настроены параметры PostgreSQL. Миграция `accounts.0002_loginthrottle_profile_device` добавляет три таблицы, не меняя существующие аккаунты и каталог. После согласованного применения выполните `manage.py check` и перезапустите сервер.

- Регистрация и вход доступны по адресам `/account/register/` и `/account/login/`. У нового аккаунта сразу появляется взрослый профиль «Основной». Для существующих аккаунтов он создаётся при первом зрительском входе, если профилей ещё нет. Служебный вход по-прежнему доступен через `/admin/`.
- Для проверки устройств войдите в один зрительский аккаунт в двух независимых сеансах Edge, например в обычном окне и InPrivate. В кабинете завершите один сеанс: его больше нельзя использовать, второй должен остаться активным.
- Для проверки детского режима создайте два детских профиля, установите PIN на одном из них с подтверждением паролем и выберите его. Доступ к опубликованному фильму 16+ должен исчезнуть из каталога, карточки и публичных медиа. Выберите детский профиль без PIN и попытайтесь перейти на взрослый: потребуется PIN исходного профиля. Пять неверных попыток блокируют проверку на 15 минут для аккаунта, включая другие устройства.
- Для восстановления пароля отправьте запрос из зрительской формы. На учебном стенде письма не уходят наружу: они сохраняются в `private/mail` либо в каталоге `CINEMA_MAIL_DIR`. Используйте непубличный каталог с доступом только для оператора. Откройте ссылку из последнего письма: она действует 30 минут и только до успешного сброса. После смены или сброса пароля зрительские сессии отзываются.
- Для проверки удаления используйте отдельный учебный аккаунт. Без верного текущего пароля удаление не выполняется. После подтверждения данные аккаунта, профили и сессии удаляются, ссылка на исполнителя в журнале обнуляется. Платежи, подписки и факты просмотра появятся на следующих этапах; проверка их обезличивания отложена до этапов 4–5.

## Этап 4: подписки и тестовая оплата

Перед обновлением целевой PostgreSQL сверяйте `inspect_database`, `showmigrations` и `migrate --plan`. Если этап 3 уже применён, ожидаются только `billing.0002_paymentmethod_promocode_subscription_payment_and_more` и `operations.0002_notification`. После согласованного применения запустите `setup_roles`, `check` и перезапустите сервер.

1. В Admin создайте активный тариф и промокод на 100 %, действующий сегодня. Войдите как зритель и на странице «Тарифы» выберите тариф. Имитатор не использует реальные деньги, реквизиты карт или внешний платёжный сервис.
2. Подтвердите оформление, затем выберите успех или отказ. История, учебный способ и уведомления доступны в «Кабинет → Подписка и платежи». Повторное подтверждение той же операции не продлевает оплаченный срок.
3. Для текущего ненулевого платежа в Admin откройте «Платежи → Вернуть платёж». После подтверждения подписка прекращается. Бесплатный период прекращается отдельно; денежного возврата для него нет.
4. Для проверки продления на изолированном стенде подготовьте период с включённым автопродлением, у которого время окончания уже прошло. Выполните `& $python manage.py process_subscriptions` дважды. При наличии способа появится один новый оплаченный период, без способа — уведомление и отметка ручного повтора. После привязки способа команда не должна обрабатывать помеченный период: используйте «Повторить продление» в кабинете.

Просмотр полных фильмов и закрытие активных сеансов плеера при прекращении доступа относятся к этапу 5. Полный центр уведомлений относится к этапу 7.

## Этап 5: плеер, история и скачивание

Перед обновлением выполните `inspect_database`, `showmigrations` и `migrate --plan`. После этапа 4 ожидается только `viewing.0001_initial`: она создаёт таблицы сеансов, личной истории и фактов просмотра. Применяйте миграцию только после сверки плана и затем перезапустите сервер.

1. Опубликуйте фильм с демонстрационным файлом `private/online-cinema-probe.mp4` в качестве полного видео. Чтобы проверить варианты, добавьте вторую запись видео той же длительности с другим вариантом и файл WebVTT как субтитры. У разрешённого варианта включите «Разрешено скачивание».
2. Войдите зрителем с активной подпиской и перейдите в плеер из карточки. Перемотайте видео примерно на 30 % и нажмите паузу. После обновления страницы или открытия «Продолжить просмотр» проверьте позицию. При лимите в один сеанс отдельная вкладка или второе устройство не должны получить новый слот.
3. Закройте вкладку и подождите не менее двух минут с последней активности. Продолжение должно создать новый сеанс и сохранить позицию. «Начать заново» заменяет текущий слот и сбрасывает позицию. Достижение 95 % отмечает фильм просмотренным; последующая перемотка не снимает отметку.
4. На учебном стенде замените MP4 действующего качества. Следующий запрос к прежней версии должен вернуть `410`, а «Повторить» загрузить текущую версию с сохранённой позиции. После отзыва устройства или подтверждённого возврата новые фрагменты не выдаются. Уже загруженные данные могут остаться в буфере.
5. Проверьте скачивание через карточку. Оно не занимает слот плеера. Уже скачанный файл можно открыть локально; отозвать сохранённую копию невозможно.

Команда `& $python manage.py cleanup_playback` удаляет закрытые более суток назад и давно истёкшие сеансы, не удаляя позиции и факты просмотров. Полные видео и субтитры не подключайте к публичной раздаче.

## Этап 6: избранное, отзывы и рекомендации

Перед обновлением проверьте `inspect_database`, `showmigrations` и `migrate --plan`. После этапа 5 ожидается `catalog.0002_favorite_review`: она добавляет таблицы избранного и отзывов. После согласованного применения выполните `setup_roles`, `check` и перезапустите сервер.

1. Войдите зрителем и откройте опубликованный фильм. Добавьте его в избранное, поставьте оценку и проверьте среднее в карточке и каталоге. Фильтр минимального рейтинга исключает фильмы без учтённых оценок.
2. Добавьте текст отзыва: до одобрения текст скрыт, а оценка временно не учитывается. В отдельной сессии войдите аккаунтом из группы «Модераторы» и откройте `/moderation/reviews/`. Опубликуйте или отклоните отзыв. Для отклонения и снятия с публикации требуется причина.
3. Проверьте статус и причину в «Кабинет → Мои отзывы». Удалите только текст: оценка сохраняется и снова входит в рейтинг. Ограничение автора действует на все его профили, но не мешает ставить оценки и удалять свой текст.
4. Для проверки рекомендаций подготовьте два профиля подписчика с разными жанрами в истории или избранном. В «Кабинет → Рекомендации» должны появиться фильмы соответствующих жанров, кроме уже начатых и недоступных по возрасту. Если совпадений нет, показываются доступные новинки.

### Учебная витрина

**Каталог для защиты.** В Django Admin откройте «Фильмы → Добавить демо-фильмы → Опубликовать каталог для защиты». Действие создаёт отдельные карточки полных версий «Большого Бака Банни» и «Синтел», а также «Демонстрационный ролик», затем снимает карточки фрагментов с публикации без удаления их истории. Оно не заменяет MP4 на старых карточках. Полное видео доступно подписчику, скачивание включено только для демонстрационного ролика.

- **Big Buck Bunny:** Blender Foundation, [CC BY 3.0 и условия атрибуции](https://peach.blender.org/about/). [Постер](https://peach.blender.org/2007/12/fluffy-puffy-peach-posters/) — `private/official-posters/bunny.jpg`; [официальный трейлер](https://peach.blender.org/trailer-page/) — `private/open-films/bunny-trailer.mp4`. [Исходный архив фильма](https://download.blender.org/peach/bigbuckbunny_movies/BigBuckBunny_320x180.mp4.zip) сохранён как `private/open-films/bunny-original.zip`. Для плеера используется `bunny-full.mp4`, перекодированный без обрезки, с титрами.
- **Демонстрационный ролик:** оригинальные тестовые полосы и тон, сгенерированные для проекта на этапе 1. Исходник — `private/online-cinema-probe.mp4`; JPEG-постер и 12-секундный трейлер подготовлены из него.
- **Синтел (2010, 15 мин):** [Blender Foundation, CC BY 3.0](https://durian.blender.org/sharing/). [Постер](https://commons.wikimedia.org/wiki/File:Sintel_poster.jpg) — `private/official-posters/sintel.jpg`, [официальный трейлер](https://durian.blender.org/download/) — `private/open-films/sintel-trailer.mp4`. Полный MP4 — `private/open-films/sintel-full.mp4`, копия предоставленного файла из «Загрузок» без обрезки и перекодирования: 14:48, 129,24 МБ, H.264/AAC. Прежняя карточка с фрагментом сохраняет историю, но скрывается после публикации полной версии.

На предыдущем варианте учебного стенда использовались демонстрационные фрагменты на 60 и 35 секунд. При подготовке каталога для защиты созданы отдельные карточки полных версий; старые карточки снимаются с публикации без удаления истории. Фактический состав каталога зависит от выполнения действия публикации на конкретном стенде.

На локальном стенде суперпользователь может открыть «Фильмы → Добавить демо-фильмы». Нужны применённая миграция отзывов, FFprobe и файл `private/online-cinema-probe.mp4`. Готовые карточки с теми же названиями пропускаются. Постеры и обложки создаются для каждого фильма; для трейлера и полного видео используется один и тот же тестовый ролик. Отзывы помечены как демонстрационные.

## Этап 7: администрирование, поддержка и отчёты

Установите зависимости из `requirements.txt` (для выгрузки XLSX нужен openpyxl). Сверьте `inspect_database`, `showmigrations` и `migrate --plan`: поверх этапа 6 ожидается `operations.0003_auditentry_subject_user_alter_auditentry_actor_and_more`. После согласованного применения запустите `setup_roles`, `check` и перезапустите сервер.

- Зритель создаёт обращение через «Кабинет → Поддержка». Администратор открывает его из Admin, выбирает готовую фразу, при необходимости добавляет пояснение и сохраняет статус. Ответ приходит в «Кабинет → Уведомления».
- Для проверки рассылки включите её у одного зрителя и оставьте выключенной у другого. В Admin откройте «Рассылка». Повтор той же формы не создаёт второй доставки. Служебные уведомления приходят независимо от согласия.
- В разделе «Отчёты» выберите период и выгрузите CSV или XLSX. Даты включительны по московскому времени. В журнале доступны фильтры по дате, действию и результату.

### Резервная копия и учебное восстановление

Для наполнения локального стенда суперпользователь может запустить два отдельных действия: «Фильмы → Добавить демо-фильмы» и «Учебные данные» на главной Admin. Второе действие создаёт вымышленных зрителей с адресами `example.test` и без пароля для входа. Оно добавляет связанные профили, отзывы, подписки, платежи, обращения, уведомления и историю. Повторный запуск пропускает уже существующих зрителей; служебные сессии и записи резервного копирования не имитируются.

Задайте `$env:POSTGRES_BIN_DIR = 'C:\Program Files\PostgreSQL\17\bin'` в терминале сервера либо добавьте инструменты PostgreSQL в `Path`. В Admin выберите «Создать копию». Архив сохраняется в `private/backups` или в закрытом каталоге `CINEMA_BACKUP_DIR`. Доступ к каталогу оставьте только оператору. Копия содержит БД, но не видео, изображения или файлы тестовой почты.

Для восстановления используйте только доверенную копию этого проекта и отдельную пустую локальную базу с именем `restore_*`. Создайте её вручную, затем из терминала с параметрами подключения **исходной** базы выполните:

```powershell
& $python manage.py restore_backup '<имя архива из Admin>' restore_stage7
```

Команда не очищает базы и отказывается восстанавливать архив в исходную или непустую базу. Результат успешного восстановления записывается в журнал восстановленной базы. Для проверки запустите приложение с отдельным `DB_NAME` и тем же набором разрешённых медиафайлов.
